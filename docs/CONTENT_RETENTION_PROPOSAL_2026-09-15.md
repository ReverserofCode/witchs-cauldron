# 재방문 콘텐츠 기획안 — 공방 실험실과 미니게임

- 작성일: 2026-09-15 (Asia/Seoul)
- 상태: 검토용 제안. 콘텐츠 제작·기능 구현·배포 전 단계.
- 목표: 방문자가 짧은 놀이를 즐긴 뒤, 새로운 문제와 자신의 기록을 확인하러 다른 날 다시 방문하도록 한다.
- 안 A: 월·수·금 공개하는 포션 퍼즐 + 개인 실험 노트, 4주 파일럿.
- 안 B: 한 버튼 미니게임 「포션 불조절」 + 오늘의 도전 + 개인 기록, 4주 파일럿. 상세는 12절.
- 선택 상태: 재검토 후 **안 B 포션 불조절을 첫 개발 대상으로 권장**한다. 사용자가 구현을 확정한 상태로 간주하지 않으며, 이번 작업은 개발 계획 작성까지다. 최종 권장 범위와 실행 문서는 13절을 따른다.

## 1. 안 A: 정기 퍼즐 요약

**「공방 실험실」을 작은 상설 코너로 제안한다.** 방문자는 주어진 단서로 재료를 골라 가상의 포션을 완성한다. 한 문제의 목표 이용 시간은 1~3분이다. 월·수·금 오전 9시(KST)에 새 문제가 공개되고, 지난 문제는 계속 풀 수 있다.

재방문 동기는 세 가지다.

1. 새 문제: 다음 공개 시점과 주제를 미리 알 수 있다.
2. 작은 성취: 문제를 해결하거나 해설을 읽으면서 규칙을 익힌다.
3. 누적 기록: 자신이 해본 실험을 개인 노트에서 다시 볼 수 있다.

이 효과는 검증할 가설이다. 팬사이트 이용자가 포션 테마의 퍼즐을 좋아하는지, 이용이 기존 방송 콘텐츠 탐색으로도 이어지는지는 파일럿에서 확인한다.

4~7절과 9~10절의 문제 제작·편성·범위는 안 A 기준이다. 안 B를 선택하면 12절의 게임 범위를 적용하며, 수작업 문제 12세트는 제작하지 않는다. 8절의 동일 브라우저 기준 재방문 측정 원칙과 분석 보강 필요성은 두 안에 공통으로 적용한다.

## 2. 전제와 선정 기준

사용자는 영상의 입문 적합성을 일관되게 판정하기 어렵다고 판단해 영상 선별 기반 기획을 폐기했다. 이번 안은 공개 영상의 재미·적합성 평가, 방송 장면의 수작업 발굴, 팬덤 지식의 정답 판정에 의존하지 않는다.

현재 [운영 홈](https://moingfans.com/)에는 영상·숏폼·방송 일정·팬아트가 있고, [방송 모아보기](https://moingfans.com/broadcasts)는 날짜별 다시보기와 브라우저 내 시청 표시를 제공한다. 다음 기준으로 신규 콘텐츠를 비교했다.

- 적은 방문자 수에서도 한 사람이 충분히 즐길 수 있는가?
- 새로 방문할 이유와 갱신 주기를 설명할 수 있는가?
- 정답·발행 여부·이용 상태를 명확하게 정의할 수 있는가?
- 콘텐츠를 미리 제작하고 운영 시간을 예측할 수 있는가?
- 모잉을 잘 모르더라도 참여할 수 있는가?

실제 방문자 수, 현재 재방문율, 운영자의 가용 시간은 조회하거나 확정하지 않았다. 아래 시간과 판정 기준은 운영 가능성을 검토하기 위한 제안값이다.

## 4. 핵심 콘텐츠

### 4.1 오늘 열려 있는 실험

홈의 라이브 상태 아래에 진입 카드 하나를 둔다. 상세 페이지 경로는 `/lab`을 제안한다.

**화면 문구 예시**

> 공방 실험실 · 밤이슬 포션
>
> 여섯 가지 재료 중 세 가지를 골라 주세요. 단서는 세 개!
>
> 약 1~3분 · [실험 시작]
>
> 다음 실험: 수요일 오전 9시

이름과 문구는 팬사이트의 창작 콘텐츠다. 모잉의 실제 발언이나 공식 세계관 설정으로 소개하지 않는다.

**공통 규칙**

- 재료 6개 중 서로 다른 3개를 선택한다. 배합 순서는 고려하지 않는다.
- 재료에는 종류·온도 성질 같은 명시적인 속성이 있다.
- 화면에 표시된 모든 단서를 만족하는 조합을 찾는다.
- 모든 문제는 가능한 20개 조합 중 정답이 정확히 하나여야 한다.
- 재료의 이름·속성·단서를 바꾸되 기본 조작과 규칙은 유지한다.
- 하루의 정답과 다른 날의 정답 조합이 같을 수는 있지만, 문제 전체를 이름만 바꿔 반복하지 않는다.

**한 번의 이용 흐름**

1. 문제 제목, 예상 시간, 단서를 읽는다.
2. 재료 3개를 선택하고 ‘섞어 보기’를 누른다.
3. 맞으면 완성된 포션과 짧은 해설을 본다.
4. 틀리면 충족하지 못한 단서를 확인하고 다시 시도한다.
5. 언제든 단계별 힌트나 정답·해설을 열 수 있다.
6. 실험 기록과 다음 공개 일정을 확인한다.

정답·해설 확인도 정상적인 이용 경로다. 제한 횟수와 제한 시간은 두지 않는다. 텍스트와 도형을 함께 사용해 색상만으로 재료를 구분하지 않으며, 드래그 대신 버튼 선택으로도 모든 조작이 가능해야 한다.

### 4.2 나의 실험 노트

노트는 같은 브라우저에서 참여한 기록을 모아 보여 준다.

- 문제별 상태: 미시작 / 실험 중 / 해결 / 해설 확인.
- 힌트를 보고 정답을 맞힌 경우도 ‘해결’이며, 먼저 정답을 연 경우는 ‘해설 확인’으로 구분한다.
- 이번 주에 경험한 서로 다른 문제 수와 지난 문제 목록을 표시한다.
- 공개가 지난 문제도 언제든 풀고 기록을 남길 수 있다.
- 연속 출석이 끊겨도 기존 기록은 유지한다.
- 브라우저 데이터를 지우거나 다른 기기를 사용하면 기록이 이어지지 않음을 노트에 안내한다.
- 저장 기능을 사용할 수 없어도 해당 페이지에서 퍼즐은 이용할 수 있다.

초기 노트는 날짜·문제명·상태로 충분하다. 수집용 이미지, 상점, 순위표, 계정 동기화는 파일럿 범위에 넣지 않는다.

### 4.3 기존 사이트와의 연결

실험 뒤에는 기존의 방송 상태와 일정에 접근할 수 있는 작은 링크를 제공한다. 일정이 비어 있으면 확인된 공식 채널로 연결한다. 영상 추천이나 시청을 실험의 조건으로 삼지 않는다.

게임만 이용하는 방문이 늘어날 가능성도 있다. 따라서 사이트 전체 재방문과 함께 방송·일정·공식 채널 탐색 비율을 관찰한다. 콘텐츠의 팬사이트 적합성을 판단하는 보조 근거로 사용한다.

## 5. 문제 예시 — 밤이슬 포션

아래는 기획 검토를 위한 창작 튜토리얼 예시이며, 배포할 문제 목록이 아니다.

| 재료 | 종류 | 성질 |
|---|---|---|
| 달빛잎 | 잎 | 차가움 |
| 햇살잎 | 잎 | 따뜻함 |
| 서리버섯 | 버섯 | 차가움 |
| 불꽃버섯 | 버섯 | 따뜻함 |
| 별빛가루 | 가루 | 차가움 |
| 태양가루 | 가루 | 따뜻함 |

**단서**

1. 잎, 버섯, 가루를 하나씩 넣는다.
2. 잎과 버섯은 같은 온도 성질을 가져야 한다.
3. 따뜻한 재료는 정확히 하나만 넣는다.

**정답:** 달빛잎 + 서리버섯 + 태양가루.

**해설:** 잎과 버섯이 모두 따뜻하면 따뜻한 재료가 두 개가 되므로 세 번째 단서에 맞지 않는다. 따라서 둘 다 차가워야 하고, 가루 하나만 따뜻해야 한다.

객관적인 검수 항목은 ‘정답이 하나인가’, ‘단서가 모순되지 않는가’, ‘해설이 단서와 일치하는가’다. 재미와 난이도는 실제 이용 관찰로 따로 확인한다.

## 6. 발행과 편성

### 공개 정책

- 월·수·금 오전 09:00 KST에 문제 1개씩 공개한다.
- 모든 방문자에게 같은 발행 일정과 문제를 제공한다.
- 최초 공개 전에는 시작 일정을 안내한다. 공개 이후 다음 발행 시각까지는 가장 최근 문제를 제공한다.
- 각 문제에는 회차와 공개 날짜를 표시한다. 새 문제가 없는 화·목·주말에 ‘오늘 새 문제’라고 표시하지 않는다.
- 진행 중인 문제는 유지하며, 새로운 회차가 실제 공개된 경우에만 해당 회차로 이동할 선택지를 보여 준다.
- 이미 공개한 문제와 해설은 파일럿 종료 후에도 다시 볼 수 있다.
- 후속 편성이 없으면 마지막 회차에 파일럿 종료와 지난 문제 이용 안내를 표시한다. 존재하지 않는 다음 문제를 예고하지 않는다.

### 4주 편성 예시

| 주차 | 월요일 | 수요일 | 금요일 | 목적 |
|---|---|---|---|---|
| 1주 | 밤이슬 포션 | 거품 줄이기 | 빛나는 잉크 | 기본 규칙과 힌트 익히기 |
| 2주 | 이슬 정원 | 온기 보관병 | 향기 주머니 | 같은 규칙에서 조합 조건 변화 |
| 3주 | 작은 구름 | 반짝이는 종이 | 고요한 찻잔 | 쉬운 문제와 한 단계 긴 추론 배치 |
| 4주 | 서리 유리병 | 무지개 비누 | 공방의 마지막 주문 | 반복 이용과 다음 편성 수요 확인 |

이는 주제·편성 예시다. 실제 재료·단서·정답·힌트·해설 12세트를 제작하고 검증한 뒤 발행을 예약한다. 추론 난이도가 매주 계속 상승하는 구조는 피한다.

## 7. 제작과 운영

**문제 제작 순서**

1. 같은 형식으로 재료와 속성, 단서, 정답을 작성한다.
2. 가능한 모든 조합을 검사해 정답이 하나인지 확인한다.
3. 검수자가 단서만으로 풀고 힌트·해설을 확인한다.
4. 초심자가 규칙을 이해하는 시간과 포기 지점을 확인한다.
5. 공개 일정, 다음 회차, 마지막 회차 안내를 점검한다.

최초 12문제를 완성해 두고 4주를 운영한다. 별도 콘텐츠 관리 시스템 없이 버전 관리되는 구조화 데이터로 시작할 수 있다. 문제를 수학적으로 검사하는 도구와 사용자 기능의 구체적 구현은 후속 설계 범위다.

**시간 예산 — 개발 시간을 제외한 추정**

| 작업 | 가정 | 예상 시간 |
|---|---|---|
| 문제 작성·검산 | 문제당 30~45분, 12문제 | 6~9시간 |
| 안내 작성·편성·초심자 검토 | 최초 1회 | 4~5시간 |
| 초기 편집 작업 합계 | 재사용할 기본 규칙 포함 | 10~14시간 |
| 사전 제작분 운영 | 오류 확인·지표 확인 | 주 40~60분 |
| 같은 빈도로 후속 문제 제작 | 매주 3문제 추가 | 주 1.5~2.25시간 추가 |

계속 운영할 때의 총 편집 시간은 주 약 2시간 10분~3시간 15분으로 예상한다. 실제 소요 시간은 첫 문제 세트를 만들며 기록한다. 주 1시간 이내로 운영해야 한다면 공개 빈도를 주 1회로 낮추는 편이 현실적이다.

운영자는 편성과 발행을 담당하고, 별도 검수자 또는 검증 도구가 정답의 유일성을 확인한다. 소규모 운영에서 같은 사람이 담당할 수 있으나, 데이터 입력만으로 검수를 완료했다고 간주하지 않는다.

## 8. 효과 측정

### 핵심 지표

**7일 내 사이트 재방문율**

- 기준 집단: 퍼즐을 처음 시작한 날을 KST 날짜 D로 기록한, 분석 식별자가 있는 서로 다른 브라우저.
- 분자: D+1일부터 D+7일까지 사이트에 한 번 이상 다시 방문한 브라우저 수.
- 분모: D+7일의 종료까지 관찰이 끝난 기준 집단의 브라우저 수.
- 같은 날 새로고침과 재접속은 재방문으로 계산하지 않는다.
- 이는 정확히 7일째에 돌아오는 D7 유지율과 다른 지표다.

**7일 내 퍼즐 재이용률**은 같은 집단 중 D+1일부터 D+7일까지 다시 퍼즐을 시작한 브라우저의 비율이다. 사이트에 돌아오는 효과와 콘텐츠 자체를 다시 이용하는 효과를 구분한다.

### 보조 지표

| 지표 | 확인할 내용 |
|---|---|
| 실험 카드 노출 대비 시작률 | 홈에서 콘텐츠를 발견하고 관심을 보이는가 |
| 해결·해설 확인 비율 | 규칙과 난이도가 적절한가; 두 상태는 구분해 기록 |
| 7일 동안 이용한 서로 다른 문제 수 | 한 번의 호기심 이후 다른 회차도 찾는가 |
| 실험 이후 방송·일정·공식 채널 클릭률 | 팬사이트의 기존 목적과 연결되는가 |
| 실제 제작·유지 시간 | 공개 주기를 지속할 수 있는가 |

### 분석 해석

- 비율마다 브라우저 수와 관찰 기간을 함께 적는다.
- 처음 관측된 브라우저와 기존 방문 브라우저는 가능하면 나누어 본다.
- 참여자와 비참여자의 재방문율 차이에는 원래의 팬 충성도 차이가 섞인다. 파일럿 수치만으로 퍼즐이 재방문을 증가시켰다고 단정하지 않는다.
- 충분한 트래픽이 확인되면 후속 단계에서 무작위로 홈 진입 카드를 노출하는 비교 실험을 설계한다. 이때 분모는 실제 참여자만이 아니라 최초 배정된 전체 대상이어야 한다.
- 계정이 없으므로 지표는 사람 단위가 아닌 브라우저 식별 기준이다. 저장소 초기화·차단·기기 변경으로 관측이 끊길 수 있다.
- 기존 재방문 통계 화면만으로 콘텐츠별 7일 추적이 가능한 것으로 가정하지 않는다. 노출·첫 시작·후속 방문을 연결하는 계측과 집계가 필요하다.

### 현재 분석 기반에서 필요한 보강

코드 확인 결과, 현재 `returningVisitorRate`는 선택한 기간의 방문자가 그 이전 30일 범위에도 방문했는지를 보는 지표다. 위에서 정의한 최초 퍼즐 이용 이후 7일 지표와 구분해 유지한다.

- **관찰 식별자:** 현재 `wc_session` 쿠키는 최초 발급부터 30일 후 만료되고 매 방문 때 연장되지 않는다. 첫 퍼즐 이용 직후 기존 쿠키가 만료되는 경우를 고려해야 한다. 최초 이용부터 7일 관찰에 사용할 익명 식별자의 연속성을 확보하는 설계를 구현 전에 정한다. 기존 정책 변경 또는 파일럿용 식별자 도입의 영향을 검토하며, IP나 기기 간 추정 연결로 보정하지 않는다.
- **실제 복귀 관측:** 현재 페이지뷰는 `sessionStorage`로 동일 경로의 중복 전송을 막는다. 열어 둔 탭으로 다음 날 돌아오는 방문이 누락될 수 있으므로 별도의 일자별 활성 방문 관측이 필요하다. 탭이 배경에서 자정을 넘긴 것만으로는 복귀로 세지 않고 전경 복귀나 실제 상호작용을 확인한다.
- **이벤트 구분:** 실험 카드 노출, 퍼즐 시작, 해결 또는 해설 확인, 일자별 사이트 활성 방문을 구분한다. 문제 ID·파일럿 버전·서버 수신 시각을 연결하고 반복 클릭을 고유 브라우저 기준으로 중복 제거한다.
- **계약과 집계:** 현재 이벤트 종류와 추가 정보의 허용 목록은 제한되어 있다. 수집 계약·클라이언트 타입·집계를 함께 보강해야 하며, 임의 필드를 보내는 것만으로 새 지표를 얻을 수 없다.
- **수집 범위:** 노트와 풀이 과정은 브라우저에 두고, 분석에는 필요한 최소 행동 정보만 보낸다. 식별 또는 수집이 차단된 방문은 계측 가능 집단의 분모에 포함하지 않는다.

이 보강을 하지 않으면 이용 횟수는 셀 수 있어도 이번 기획의 핵심인 7일 재방문을 일관되게 평가하기 어렵다.

## 9. 4주 파일럿과 판단 기준

**공개 전**

- 12문제 모두 정답이 정확히 하나이며 해설이 맞는지 확인한다.
- 초심자 5명을 대상으로 규칙 이해를 확인한다. 3명 이상이 3분 안에 기본 조작과 목표를 이해하지 못하면 안내를 수정한다.
- 노트 저장, 저장 차단 시 이용, 모바일·키보드 조작, 공개 시각을 확인한다.
- 분석 이벤트가 적절히 기록되고 자체 검증 트래픽은 결과에서 제외되는지 확인한다.

**운영 기간**

- 1주차: 시작률, 설명 이해, 오답·해설 이용 상황을 확인한다.
- 2~3주차: 다른 날짜 재이용과 제작 시간을 확인한다.
- 4주차: 관찰 기간이 충분한 집단의 재방문·재이용을 정리한다. 최종 7일 이내에 처음 시작한 집단은 7일 지표의 분모에서 제외한다.

**판정 제안**

다음 숫자는 실측 성과나 업계 기준이 아니라 파일럿 판단을 위한 임시 운영 기준이다.

- 7일 추적이 끝난 첫 이용 브라우저가 30개 미만이면 효과 판단을 보류한다. 이를 통계적으로 충분한 표본을 보장하는 기준으로 사용하지 않는다.
- 관찰 브라우저가 30개 이상일 때 퍼즐의 7일 내 재이용률 20%를 후속 파일럿 검토선으로 삼는다. 이 수치만으로 정식 운영을 결정하지 않는다.
- 위 검토선에 못 미치면 진입 문구·규칙 이해·문제 반복감 중 확인된 원인을 한 가지씩 수정하거나 주 1회로 축소한다.
- 재이용이 관찰되고 운영 예산을 지킬 수 있으면 다음 4주 편성을 검토한다. 사이트 재방문율과 팬 콘텐츠 탐색도 함께 판단한다.
- 문제가 풀리지 않거나 복수 정답이면 해당 회차를 닫고 수정 안내를 제공한다. 이용자에게 불이익을 주지 않으며 남은 회차도 재검사한다.
- 사전에 정한 주간 운영 예산을 2주 연속 넘으면 발행 빈도를 낮춘다.

## 10. 초기 범위와 후속 후보

**파일럿에 포함**

- 홈 진입 카드 1개와 공방 실험실 페이지.

- 주간 회고: 자신의 실험 기록을 한 장으로 보여 주기.

## 12. 안 B: 간단한 미니게임 제공안

### 12.1 후보와 추천

| 게임 | 조작과 한 판 길이 | 반복할 이유 | 제작·운영상 고려점 |
|---|---|---|---|
| **포션 불조절** | 버튼 하나로 온도 표시 멈추기, 5라운드 약 30~60초 | 정확도를 높여 개인 기록 갱신; 오늘의 목표 배치 도전 | 설명이 짧고 공방 테마에 적합. 반응속도·움직임 인지가 필요 |
| **포션 짝맞추기** | 12장 중 같은 재료 6쌍 찾기, 약 1~2분 목표·시간제한 없음 | 더 적은 시도로 완료; 오늘의 카드 배치 | 익숙한 규칙과 낮은 조작 부담. 재도전 때 배치 암기로 점수가 좋아질 수 있음 |
| **재료 받기** | 솥을 좌우로 움직여 재료 받기, 한 판 60초 | 받기 성공과 연속 점수 기록 | 터치 가림·화면 크기·충돌 판정의 검증 범위가 큼 |

**미니게임 중 첫 추천은 포션 불조절이다.** 한 손으로 조작하고 짧은 시간에 결과를 볼 수 있다. 반응속도 부담이 없는 콘텐츠를 우선한다면 포션 짝맞추기로 선택을 바꿀 수 있다. 재료 받기는 첫 게임의 반응을 확인한 뒤 검토한다.

### 12.2 포션 불조절 — 실제 이용 경험

**진입 문구 예시**

> 포션 불조절
>
> 딱 좋은 온도에서 불을 꺼 주세요. 다섯 번의 배합으로 오늘의 기록에 도전!
>
> 약 30~60초 · [오늘의 도전] [연습하기]

1. 방문자가 ‘가열 시작’을 누르면 온도 표시가 눈금 위를 왕복한다.
2. 목표 온도 구간을 보고 ‘불 끄기’ 버튼을 누른다.
3. 목표 중심에 가까울수록 높은 점수를 받는다. 목표 밖이면 해당 라운드 0점이다.
4. 다음 라운드에서 목표 구간과 움직이는 속도가 달라진다.
5. 5라운드가 끝나면 합계와 개인 기록을 확인한다. 각 라운드는 최대 100점, 한 판은 최대 500점이다.

점수는 멈춘 위치와 목표 중심의 거리로 계산한다. 처음 출시할 때에는 콤보나 무작위 보너스를 넣지 않는다. 목표를 놓쳐도 다음 라운드를 계속할 수 있다. 30~60초는 예상 이용 시간이며 강제 종료 제한은 아니다.

결과에는 라운드별 점수, 오늘의 첫 완료 점수, 재도전을 포함한 오늘의 최고 점수, 다음 도전 갱신 시각을 보여 준다. ‘다시 하기’로 바로 재도전할 수 있다.

### 12.3 조작과 기록

- 모바일은 큰 버튼 한 개, PC는 같은 버튼 또는 Space 키로 조작한다. 입력 한 번이 두 번 처리되거나 키를 길게 눌러 여러 라운드가 넘어가지 않도록 한다.
- 목표 구간은 색상과 함께 테두리·눈금·문구로 구별한다. 재검토 후 첫 버전은 무음으로 축소하고 소리 켜기 옵션은 제외한다.
- 느린 연습 모드를 제공하고 기본 속도와 기록을 분리한다. 움직임 효과를 줄여도 핵심 반응 조작의 부담까지 없어지는 것은 아니므로 초심자 검토에 포함한다.
- 점수가 확정되지 않은 라운드 진행 중 탭을 벗어나거나 화면이 가려지면 진행을 멈추고, 복귀 후 그 라운드를 준비 상태에서 다시 시작한다. 점수가 확정된 라운드나 최종 결과 화면은 상태를 유지한다. 라운드 점수는 결과가 확정됐을 때 한 번만 합산한다.
- 점수 판정은 화면 프레임 수가 아니라 경과 시간과 실제 입력 시각을 기준으로 설계한다. 화면 크기는 목표 구간 비율을 바꾸지 않는다.
- 개인 기록은 이 브라우저에 저장한다. 저장이 차단되어도 해당 판은 완료할 수 있다.
- 기본 속도의 ‘오늘의 도전’끼리만 같은 기록표를 사용한다. 규칙·난도 버전이 바뀌면 기록을 분리한다.
- 같은 조건이라도 기기의 입력 지연은 다를 수 있다. 초기 기능은 개인 도전으로 제공하고 전체 이용자 순위표는 포함하지 않는다.

### 12.4 연습 모드와 오늘의 도전

**연습 모드:** 플레이할 때마다 사전에 검증한 목표 구간·속도의 조합 중에서 새 구성을 만든다. 횟수 제한 없이 이용하며 느린 속도로 규칙을 익힐 수 있다.

**오늘의 도전:** 한국시간 오전 09:00에 5라운드 구성이 바뀐다. 날짜별로 같은 규칙·난도를 선택한 방문자에게 같은 목표 구간과 속도 순서를 제공한다. 날짜가 바뀌었다는 이유만으로 새 규칙이나 새로운 그림을 제작하지 않는다.

- 도전 날짜는 서버의 공개 기준 시각으로 정한다. 오전 09:00 전에는 전날 오전 09:00에 시작한 도전이 활성 상태다.
- 구성 식별에는 도전 날짜, 게임 규칙 버전, 난도를 포함한다. 게시 버전이 같은 동안 같은 도전의 구성이 달라지지 않게 한다.
- 플레이 도중 오전 09:00을 넘겨도 시작할 때의 도전 ID에 결과를 기록한다. 종료 뒤 새 도전을 안내한다.
- 다시 시도는 가능하며 오늘의 첫 완료 점수와 반복 포함 최고 점수를 구분한다. ‘첫 기록’은 첫 라운드 시도나 실력 검증을 뜻하지 않는다.
- 날짜별 기록은 남기되 연속 방문 보너스나 미방문 벌점은 두지 않는다.

같은 날 여러 번 플레이하는 것은 재플레이이고, 다른 날짜에 돌아오는 것은 재방문이다. 두 행동을 따로 측정한다. 날짜별 구성이 달라지는 것만으로 재방문이 늘어난다고 가정하지 않는다.

재방문 날짜는 자정을 경계로 하는 KST 달력 날짜를 사용한다. 오전 09:00에 바뀌는 도전 ID와 구분하며, 같은 날 08:59와 09:01에 서로 다른 도전을 해도 다른 날짜 재방문으로 계산하지 않는다.

### 12.5 제작 방식과 최초 범위

기존 사이트 안의 별도 `/games/potion-timing` 페이지를 제안한다. 홈에는 진입 카드 한 개를 두고, 게임 코드와 효과는 해당 페이지를 열었을 때 불러오도록 구성한다.

화면은 솥, 온도 눈금, 버튼, 점수판으로 시작한다. 기존 프론트엔드 구성으로 구현 가능성을 검토하며, 첫 버전에 별도 게임 엔진을 도입할 필요는 낮다. 솥·포션·재료 표현은 직접 만든 도형과 아이콘을 사용하고, 창작 게임을 모잉의 공식 설정이나 실제 발언으로 소개하지 않는다.

**첫 파일럿 범위**

- 한 버튼 조작, 5라운드, 합계 점수.
- 기본 속도의 오늘의 도전과 자유 연습·느린 연습.
- 오늘 첫 완료·최고 기록과 간단한 과거 기록.
- 모바일·키보드 조작, 일시정지·복귀 처리.
- 시작·정상 완료·당일 재플레이·다른 날짜 재이용의 계측. 미완료 시작은24시간 관찰 후 별도로 집계하며 확정 이탈로 표현하지 않는다.

스킨 수집, 상점, 계정, 멀티플레이, 전체 순위표, 게임 여러 개 동시 출시는 포함하지 않는다. 기존 영상·방송 링크는 결과 화면의 선택 가능한 이동 경로로 제공한다.

초기 제작에는 게임 화면·상태 전환·입력 판정·난도 설정·저장·분석 보강 작업이 필요하다. 기존 안 A의 문제 편집 시간 10~14시간을 게임 개발 시간으로 해석하지 않는다. 개발 일정은 구현 환경과 범위를 확인한 뒤 산정한다.

출시 후에는 신규 문제 원고의 정기 제작을 요구하지 않는다. 오류·기기별 조작·반응·분석을 확인하는 데 주 30~60분의 운영 예산을 가정하고 실제 소요 시간을 기록한다. 조작 오류와 재미의 부족을 개선하는 개발 시간은 이 예산과 별도다.

### 12.6 포션 짝맞추기로 선택할 경우

- 서로 다른 재료 6종을 2장씩 배치해 카드 12장을 만든다.
- 두 장을 고를 때마다 시도 1회를 기록한다. 같은 재료이면 공개 상태로 남는다.
- 다른 재료이면 방문자가 ‘다시 덮기’를 눌러 진행한다. 짧은 자동 타이머로 카드를 숨기지 않는다.
- 6쌍을 찾으면 완료한다. 점수 대신 시도 횟수를 표시하며, 시간제한은 없다.
- 오늘의 배치는 오전 09:00에 바뀐다. 같은 배치의 첫 완료 기록과 재도전 기록은 구분한다.
- 재료는 이름과 기호를 함께 표시한다. 카드 버튼은 키보드로도 선택할 수 있어야 한다.
- 개인 기록과 오늘의 도전 운영 원칙은 불조절 게임과 공유하되, 서로 다른 게임의 점수는 비교하지 않는다.

이 안을 선택하면 불조절 게임은 함께 제작하지 않는다. 한 게임의 이용 수요를 먼저 확인한다.

### 12.7 4주 확인 계획

1. 공개 전: 첫 이용자가 설명만으로 조작할 수 있는지, 입력과 점수의 연결이 납득되는지 확인한다.
2. 1주차: 시작 후24시간 관찰 완료율과 조작 문의를 확인한다. 첫 라운드 이탈률·기기별 전환율은 최소 계측 범위에 없으므로 시제품의 직접 관찰과 구분한다.
3. 2~3주차: 같은 날 재플레이와 다른 날짜 복귀를 구분하고 기본·느린 모드 이용을 확인한다.
4. 4주차: 7일 관찰이 끝난 집단만 중간 집계하고 운영 부담을 함께 판단한다. 모집28일 이후7일을 더 관찰하며, 모집 시작부터35일이 경과한 시점에 전체 모집 집단을 최종 집계한다.

8절의 ‘퍼즐 첫 시작’을 이 안에서는 ‘게임 첫 시작’으로 바꾸어 적용한다. 완료되지 않은 첫 플레이도 첫 시작 집단에 포함한다. 완료한 이용자만 분모에 넣어 재방문율을 높게 보이게 하지 않는다.

9절의 최소 관찰 규모와 20% 재이용 검토선은 안 B에 자동 적용하지 않는다. 미니게임은 시작·완료·조작 이해에 대한 초기 관찰을 바탕으로 별도 운영 판단선을 정한다. 개선 효과를 인과적으로 주장하려면 후속 비교 실험이 필요하다.

첫 이용률은 높지만 다른 날 재이용이 낮으면, 같은 날 점수 갱신만으로 만족하는 게임일 수 있다. 이 경우 상설 짧은 놀이로 유지할 가치와 재방문을 위한 추가 투자 가치를 구분해 판단한다. 조작 오류가 확인되면 해당 모드를 먼저 수정하고, 검증 전 순위·보상 요소로 참여를 유도하지 않는다.

## 13. 재검토 결과와 개발 계획

### 13.1 권장 순서

**포션 불조절 하나를 먼저 검증한다.** 근거는 공방 테마와 낮은 반복 원고 제작 부담이며, 재방문 효과가 입증됐기 때문이 아니다. 퍼즐·투표·새소식·복수 게임을 동시에 출시하지 않는다. 사용자가 폐기한 영상 선별 입문 가이드는 제외한다.

| 단계 | 개발 결과 | 다음 단계 조건 |
|---|---|---|
| 1. 연습 시제품 | 5라운드·점수·한 버튼·느린 연습·숨김/복귀 | 입력 오류 해결, 실제 이용자의 조작 이해 확인 |
| 2. 일일 도전/개인 기록 | 서버 KST09시·동일 날짜 구성·첫/최고·브라우저 기록 | 시간 경계·저장 장애·모드 격리 검증 |
| 3. 통합/측정 | 경량 홈 카드·메뉴·독립 파일럿 분석 | 기존 기능 회귀 없음, 지표·안내·삭제 운영 준비 |
| 4. 공개 준비 | 브라우저·무키 빌드·DB 격리 테스트·리뷰·중단 절차 | 필수 검증 완료 및 후속 릴리스 범위 확인 |
| 5. 효과 관찰 | 28일 모집 +7일 추가 관찰 | 성숙 집단의 재이용·운영 부담으로 유지/개선 판단 |

반응 조작 장벽이 크면 시제품 단계에서 수정하거나 포션 짝맞추기로 전환을 검토한다. 실패한 시제품 위에 기록·보상·순위 기능을 계속 추가하지 않는다. 재이용 자료가 적을 때는 ‘판단 자료 부족’으로 보고한다.

### 13.2 재검토로 바뀐 범위

- 소리 옵션, 순위, 보상, 여러 게임 동시 개발은 제외한다.
- 날짜·입력·기록의 모호한 부분을 명세화한다. 첫 START 전 만료는 재조회, 시작한 판의09시 통과는 기존 도전 유지다.
- 기존 분석의 재방문율을 게임 첫 이용 후7일 지표로 재사용하지 않는다. 전용 브라우저 ID와 별도 집계를 사용하되 점수·IP·UA는 신규 수집하지 않는다.
- 노출 대비 시작률·첫 라운드 이탈·기기별 전환은 최소 분석에 포함하지 않는다. 기존 제안의 해당 측정을 했다고 보고하지 않는다.
- 소스 스위치 비활성화는 재빌드·재배포가 필요하다. 즉시 원격 중단으로 표현하지 않는다.
- 신규 파일럿 식별자는45일 만료, 정상운영 시 다음24시간 안에 운영 DB에서 삭제하는 방식으로 관리한다. 야간 정리·운영 점검·집계 제외 안내를 개발 범위에 포함한다.
