# 포션 불조절 구현·배포 기록

작업일: 2026-09-15 (Asia/Seoul). 상태: **베타 구현·테스트·운영 배포 완료**. 사람 대상 사용성 평가와 재방문 파일럿은 별도 보류 상태다.

## 범위와 과정

기존 기획을 바탕으로 포션 타이밍 게임, 일일 도전, 기기 기록, 홈/메뉴 진입, 별도 재방문 측정 기반을 구현했다. 영상 선별형 입문 가이드는 폐기된 방향으로 유지하며 상품 이미지·영상 등 허가 없는 자료를 추가하지 않았다.

원래 작업 폴더의 미커밋 계획 문서는 보존했다. 최신 `origin/main`의 `6c01ec057fcd5f93d79c392eca7273396d0ed503`에서 격리 작업 디렉터리/브랜치 `codex/potion-timing-20260915`를 생성했다. 순수 게임 규칙, UI, 측정 서버, 정리 작업을 파일 소유 범위로 분리하고 테스트 후 상호 검토한다.

초기 97개 테스트는 통과했다. 신규 테스트를 먼저 실패시키고 구현하는 순서로 진행했으며, 서버 DB 테스트는 명시된 폐기용 DB가 없는 로컬에서 skip으로 기록했다. 로컬 Docker Desktop 자체가 inference socket 초기화 오류로 시작하지 못했으므로 사용자 데이터 초기화 없이 CI의 폐기용 PostgreSQL16 및 Docker 이미지 검증으로 대체한다.

## 검토 중 보완

- 규칙 validator 삼중화를 하나로 합쳤다.
- 이미 일시정지 상태의 재일시정지, 미래 완료 기록, 비정상 시각으로 삭제하지 않음, 명시적 on/off route 테스트를 추가했다.
- 게임 클라이언트 재시도/집계 제외/자정 경계를 실제 provider browser fixture로 검증했다.
- 의존성 보안 패치와 Vitest ESM 설정 정리를 진행했다.
- 집계 SQL의 매개변수 누락, DB idle 오류/HMR pool 중복, 자정 재시도 응답 해석, 집계 제외 이후 재전송 및 저장 실패 시 수집 중단을 추가 검토에서 보완했다.
- 전체 브랜치 검토에서는 게이지 표식과 목표의 좌표계 차이 및 DB 정리 테스트의 배열 bind 오류를 발견했다. 게이지는 같은 좌표 rail을 쓰도록 보완하고 320/1440px·목표 25/70의 실제 bounding box를 비교한다. DB fixture는 배열을 하나의 SQL 매개변수로 전달하도록 수정했다.
- 일반 Analytics 수집 계약/집계의 의미는 바꾸지 않았다. [최적화 검토](CODE_OPTIMIZATION_REVIEW_2026-09-15.md)에 별도 후보를 남겼다.

## 실행 중 판단과 비용

1. 순수 domain 작업을 하나로 묶고 독립 파일 소유 작업을 병렬화했다. 잘못된 인터페이스 판단의 비용은 통합 재작업이며 task/branch review로 확인한다.
2. 사용자가 구현·배포를 승인했으므로 기술 검증된 게임을 팬 창작 베타로 공개한다. 사람 대상 사용성 결과는 만들지 않으며 파일럿은 비활성이다. 비용은 사용성 평가 이후 UI 재작업 가능성이다.
3. 스킬 도구의 요구 형식에 맞춰 구현 복사본 계획의 T/M 제목을 Task N으로 기계 변경했다. 제품 영향은 없다.
4. 배포 진행 중 복구 증거인 무시된 scratch ledger를 보존하고 판단을 이 문서로 옮긴다. 비용은 소량의 로컬 저장 공간이다.
5. 파일럿 날짜/운영 담당자가 미정이므로 null 설정 및 nightly 미예약을 유지한다. 비용은 후속 활성화 배포가 한 번 필요하다는 점이다.
6. 발견된 취약점은 호환 패치로 업데이트했다. 비용은 패치 회귀 가능성이며 전체 테스트·브라우저·Docker 검증을 거친다.
7. 고장 난 로컬 Docker를 공장 초기화하지 않고 CI에서 실제 DB/컨테이너를 검증한다. 비용은 CI 대기 시간과 로컬 Docker 증거의 부재다.
8. Vitest 설정을 .mts로 바꿔 ESM 형식을 명시했다. 비용은 도구 설정 파일명 변경뿐이다.
9. 기존 관리자 화면은 바꾸지 않고 smoke의 스크롤 가정을 수정했다. 실제 computed style은 모바일 날짜 도구막대가 static, 메뉴가 sticky임을 보여주었다. 두 속성을 먼저 검증하고 도구막대가 화면 밖으로 나간 뒤 겹침을 검사한다. 비용은 중간 스크롤 상태의 별도 시각 확인 필요성이다.
10. 선행 시작 이벤트가 없는 완료 전송은 상위 설계 명세의 204 제외 계약을 따른다. 세부 계획의 모호한 400 표현보다 명세를 우선하고 실제 ID/모드/버전 충돌은 400을 유지한다. 비용은 미출시 API의 거절 상태 구분 변경이며 클라이언트는 둘 다 재시도하지 않는다.
11. 배포 증거를 기록하는 후속 PR은 루트 AGENTS.md와 docs만 변경한다. PR CI는 유지하고, 앱/배포 코드가 기능 배포 SHA와 동일한지 확인한 뒤 문서 병합이 유발하는 중복 CD는 서버 배포 전에 취소한다. 이미 검증한 기능의 불필요한 컨테이너 재시작을 피하며, 비용은 최신 main의 문서 커밋과 실제 앱 배포 SHA를 구분해 기록해야 한다는 점이다.

## 참고 사항

- 게임과 별개로 파일럿은 시작하지 않았다. 활성화 조건은 [측정 운영 문서](POTION_RETENTION_MEASUREMENT.md)에 있다.
- 기존 배포 스크립트는 컨테이너 교체 방식이다. 무중단/zero downtime을 보장한다고 표현하지 않는다.
- 접근성 자동 검사/조작 테스트는 사람 대상 사용성 연구나 재방문 효과 입증이 아니다.
- DB 통합 테스트 skip, 기존 lint 경고, 외부 API 키 없는 빌드의 경고를 실제 실패/성공과 구분한다.
- 중단 시 `POTION_GAME_ENABLED=false`로 변경해 배포한다. 게임 집계/삭제 활성화는 별도 운영 승인·순서가 필요하다.
