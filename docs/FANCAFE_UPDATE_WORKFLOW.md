# 팬카페 업데이트 공지 워크플로우 (witchs-cauldron)

목적: `witchs-cauldron` 프로젝트 업데이트 내용을 팬카페에 일관되게 공지하고,
스크린샷(증빙/가독성)을 함께 첨부해 신뢰도를 높인다.

---

  - `https://cafe.naver.com/f-e/cafes/30182989/menus/1?viewType=L`

## 1) 사전 준비 (Release Note 초안)

### 입력값
- 배포/커밋: `<sha>`
- 프로젝트 도메인: `<domain>` (예: `https://moingfans.com`)
- 변경 요약 3~5줄
- 사용자 영향(새 기능/수정/주의사항)
- 장애/롤백 여부

### 게시용 텍스트 템플릿
```md

1) 주요 변경
- ...
- ...

2) 사용자 영향
- ...

3) 확인/주의사항
- ...

4) 서비스 주소
- 프로젝트 도메인: <domain>

5) 참고
- 배포 버전: <sha>
```

## 2) 스크린샷 가이드 (첨부용)

기본 규칙:
- **수정/추가된 기능 1개당 스크린샷 2장 필수**
  1) 기능 화면(입력/설정/진입 상태)
  2) 결과 화면(적용/완료/검증 상태)

예시:
- 기능이 3개면 최소 6장 첨부

파일명 규칙:
- `fan-update-YYYYMMDD-<feature>-01-before_or_input.png`
- `fan-update-YYYYMMDD-<feature>-02-after_or_result.png`

가독성 규칙:
- 본문 1문단당 2~3줄 이내, 핵심만 bullet로 작성
- 스크린샷 캡션에 "무엇이 바뀌었는지" 1줄 설명
- 민감정보(토큰/개인정보/주문번호 등) 보이면 가림 처리
- 전체 화면보다 핵심 영역 위주 캡처
- 동일 해상도 유지(가독성)

## 3) 자동화 실행 순서 (운영 절차)

1. 업데이트 요약 생성 (도메인 포함)
2. 기능 수 집계 (수정/추가된 기능 개수 N)
3. 스크린샷 캡처 (기능당 2장, 총 최소 2N장)
4. 카페 글쓰기 페이지 진입
5. 제목/본문 입력 (짧은 문단 + bullet)
6. 스크린샷 첨부 + 캡션 입력
7. 등록
8. 목록 URL에서 등록 확인
9. 링크/게시 시각 기록

3. 잘못 게시 시: 즉시 수정 또는 삭제 후 재등록
