# UI/UX and Analytics Improvement Plan

작성일: 2026-04-28

## 목적

메인 페이지 UI/UX 개선안과 운영자 Analytics 화면 개선안을 한 문서로 정리한다. 추가로 현재 수집 중인 이벤트에서 바로 추출 가능한 통계 지표와, 별도 계측을 추가해야 하는 후보 지표를 구분한다.

## 메인 페이지 UI/UX 개선안

### 현재 판단

- 데스크톱에서는 주요 섹션 정렬과 가로 오버플로우 문제가 크지 않다.
- 모바일에서는 히어로와 쇼츠가 과도하게 길어 추천 영상 이후 콘텐츠 접근성이 떨어진다.
- 정보 중요도는 추천 영상, 쇼츠, 팬아트 순서가 맞지만, 섹션 높이 때문에 체감 우선순위가 흐려진다.
- 쇼츠/클립 제어 버튼과 인디케이터는 모바일 터치 기준으로 작고 시각적 노이즈가 있다.
- 라이브 일정과 팬아트는 단일 커뮤니티 섹션으로 유지하되 모바일에서는 요약형이 적합하다.

### 개선 항목

| ID | 우선순위 | 항목 | 개선 방향 | 기대 효과 |
|---|---:|---|---|---|
| UX-01 | P1 | 모바일 히어로 높이 축소 | 프로필, 채널 바로가기, 상태 정보를 요약 스트립으로 압축 | 추천 영상 진입 시간 단축 |
| UX-02 | P1 | 쇼츠 섹션 구조 단순화 | 치지직/YouTube를 모바일 탭 구조로 전환하고 한 번에 하나만 표시 | 세로 스크롤 피로 감소 |
| UX-03 | P1 | 제어 버튼 터치 영역 확대 | 캐러셀/비디오 컨트롤은 최소 44px 터치 영역 확보 | 조작 안정성 개선 |
| UX-04 | P2 | 추천 영상 카드 밀도 조정 | 최신 업로드를 주 카드로 두고 인기/최근 목록은 보조 리스트로 압축 | 중요 콘텐츠 집중도 향상 |
| UX-05 | P2 | 라이브 일정 + 팬아트 통합 섹션 정리 | 5일 일정 요약과 팬아트 썸네일 스트립을 동일 카드 안에 배치 | 커뮤니티 섹션 높이 안정화 |
| UX-06 | P2 | 이미지 lazy-load fallback | 팬아트/헤더 아이콘에 고정 크기와 skeleton/fallback 적용 | 로딩 중 레이아웃 흔들림 감소 |

## Analytics 화면 개선안

### 기존 문제

- 방문자, 페이지뷰, 메뉴 클릭처럼 원시 카운트 중심이라 의사결정 지표가 부족했다.
- 일별 데이터가 없는 날짜는 배열에서 빠져 차트가 실제보다 연속적으로 보이지 않을 수 있었다.
- 스크롤 깊이와 섹션 조회가 이벤트 수 중심으로 표시되어 방문자 기준 도달률을 판단하기 어려웠다.
- 디바이스별 성과는 방문자 수만 보여 클릭 효율 비교가 어려웠다.
- 이벤트 구성은 일부 이벤트만 반영해 실제 수집 이벤트 전체 비중을 설명하지 못했다.

### 이번 개선 반영

- `/api/analytics/stats`의 독립 SQL을 `Promise.all`로 병렬화했다.
- 일별 트렌드는 `generate_series`로 조회 기간의 모든 날짜를 채우고, 이벤트가 없는 날은 0으로 반환한다.
- 상단 KPI에 클릭률, 재방문율, 페이지/방문, 깊은 스크롤 도달률을 추가했다.
- `totals`에 재방문자, 신규 방문자, 콘텐츠 클릭, 섹션 조회, 스크롤 이벤트, 페이지 이탈, 전체 이벤트 수를 추가했다.
- `metrics`에 페이지/방문, 클릭률, 메뉴 클릭률, 재방문율, 섹션/방문, 깊은 스크롤 도달률, 이탈률, 빠른 이탈률을 추가했다.
- 섹션 조회와 스크롤 깊이는 방문자 수와 이벤트 수를 함께 보여주도록 개선했다.
- 디바이스 카테고리는 페이지뷰, 메뉴 클릭, 디바이스별 클릭률을 함께 반환한다.
- 이벤트 구성은 `eventTypes` 전체를 기준으로 계산한다.
- 메뉴/콘텐츠 클릭을 합친 `topInteractions`를 추가해 주요 상호작용을 한눈에 볼 수 있게 했다.

## 추가 추출 가능한 통계 지표

### 현재 이벤트만으로 가능한 지표

| 지표 | 계산 기준 | 활용 |
|---|---|---|
| 재방문율 | 조회 기간 방문자 중 이전 30일 pageview가 있는 visitor 비율 | 팬층 반복 방문 추적 |
| 페이지/방문 | pageviews / visitors | 사이트 탐색 깊이 확인 |
| 클릭률 | (menu_click + content_click) / pageviews | 링크/CTA 유효성 판단 |
| 섹션 도달률 | section_view 고유 방문자 / 전체 방문자 | 콘텐츠 배치 우선순위 검증 |
| 깊은 스크롤 도달률 | 75% 이상 scroll_depth 방문자 / 전체 방문자 | 페이지 길이와 콘텐츠 소비 정도 판단 |
| 빠른 이탈률 | 10초 이하 체류 + 25% 미만 스크롤 이탈 / page_exit | 첫 화면 품질 판단 |
| 디바이스별 클릭률 | 디바이스별 menu_click / pageview | 모바일/데스크톱 CTA 차이 분석 |
| Referrer별 방문자 | referrer host별 고유 visitor | 유입 채널 품질 비교 |

### 추가 계측이 필요한 후보 지표

| 지표 | 필요한 이벤트/메타데이터 | 이유 |
|---|---|---|
| 영상 재생 시작률 | `video_play_start`, video id/type | 추천 영상과 쇼츠의 실제 소비 여부 판단 |
| 영상 재생 완료율 | `video_progress`, 25/50/75/100 threshold | iframe/MP4 콘텐츠 품질 비교 |
| 캐러셀 수동 조작률 | `carousel_next`, `carousel_previous`, `carousel_pause` | 자동 캐러셀 UX 검증 |
| 팬아트 확대율 | `fanart_open`, artwork id | 팬아트 섹션의 실제 흥미도 확인 |
| 일정 상세 열람률 | `schedule_open`, schedule id/date | 라이브 일정 정보 수요 확인 |
| CTA 위치별 전환율 | `metadata.location`, `metadata.viewport` 강화 | 헤더/히어로/푸터 링크 배치 최적화 |
| 성능 체감 지표 | Web Vitals 또는 custom timing | 디자인 변경이 UX 성능에 주는 영향 확인 |

## 권장 다음 단계

1. 메인 페이지는 `UX-01`과 `UX-02`를 먼저 구현해 모바일 첫 화면과 쇼츠 높이를 줄인다.
2. Analytics는 이번 추가 지표를 1~2주 누적한 뒤 섹션 도달률과 깊은 스크롤 도달률로 메인 페이지 레이아웃 변경 효과를 비교한다.
3. 다음 계측은 `video_play_start`, `video_progress`, `fanart_open`, `schedule_open` 순서로 추가한다.
4. 디자인 변경 전후 비교를 위해 동일 기간 대비 지표를 대시보드에 추가하는 것을 후속 작업으로 둔다.
