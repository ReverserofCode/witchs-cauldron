## 작업 범위

사용자가 승인한 `docs/superpowers/specs/2026-09-15-fanart-permission-workflow-design.md`를 구현한다. 계획은 `docs/superpowers/plans/2026-09-18-fanart-permission.md`에 있다.

- 기준: `origin/main`의 `f642625`.
- 별도 작업 트리와 `codex/fanart-permission-20260918` 브랜치 사용에 사용자 동의가 있었다.
- 원래 체크아웃과 미커밋 문서는 보존했다.
- 실제 작가 이미지·팬카페 로그인·메시지 발송·푸시·배포는 하지 않는다.

## 운영상의 한계

- 기존 정적 팬아트는 자동으로 승인하지 않는다. 신규 카탈로그의 철회 기능은 기존 정적 URL에 소급 적용되지 않는다.
- 작가의 동의와 생성형 AI 미사용 확인은 운영자가 실제로 확인해야 한다. 시스템은 그 기록과 게시 조건을 검증할 뿐 진위를 자동 인증하지 않는다.
- 외부 수집·검색·메시지 자동 발송은 제외한다.
- 철회 후 새로운 파일 요청은 차단하지만 이미 다운로드된 사본을 회수할 수는 없다.

### 실패를 통해 확인한 회귀

- UI 구현 전 브라우저 테스트는 관리자 화면 부재로 실패했다.
- 카탈로그 구현 전 4개 테스트가 실패했고 구현 후 통과했다.
- 이미지 최적화 제한 전에는 관리 이미지가 최적화 대상으로 허용되어 테스트가 실패했다. 정적 이미지 경로만 허용하도록 수정한 후 통과했다.
- 처리 기록 UI가 `action`을 읽지만 API는 `type`을 제공하는 불일치를 브라우저 assertion으로 재현했다. 저장소의 감사 이벤트 타입을 공유하고 수정한 뒤 통과했다.
- 작업 재개 시 Docker가 중지되어 DB 테스트가 연결 실패했다. 격리된 DB를 기동하고 재실행해 통과했다. 이 실패를 기능 통과로 계산하지 않았다.

## 독립 리뷰와 보완

첫 서버 리뷰의 두 지적(작가 확인과 운영자 검수 분리, 프록시에서 실효성 있는 timing-safe 인증)은 구현에 반영했다. 구현 에이전트가 사용량 한도에 도달해 화면 통합은 주 에이전트가 이어서 수행했고, 별도의 최종 코드 리뷰로 보완했다.

`de34f8f` 최종 리뷰에서 Critical 없음, Important 3개와 Minor 1개를 발견했다:

1. 철회된 선택 항목 때문에 닫힌 모달이 자동회전 후 다시 열릴 가능성.
2. 게시 직전 저장된 파일의 존재/해시 재확인 누락.
3. 프록시와 API가 환경변수 자격증명 공백을 다르게 취급.
4. legacy 파일이 없으면 메인 갤러리를 마운트하지 않는 조건.

수정 커밋 `b35f0dc`에서 네 항목을 모두 보완했다. 별도 리뷰어의 scoped 재검토 결과 **4개 모두 해결, 신규 Critical/Important 없음**이다.

- 저장 파일 유실·변조는 실제 임시 이미지 파일로 재현했다. 게시 시 409를 반환하고 준비 상태를 유지한다. 파일 확인 중 다른 관리자가 교체한 경우도 버전 검증으로 막는다. 이미 성공한 게시의 재시도는 멱등성을 유지하고, 미디어 요청은 별도로 현재 파일을 검증한다.
- 정확한 공백 포함 자격증명 회귀 테스트와 빈 legacy/게시된 카탈로그·빈 카탈로그 홈 렌더링 테스트를 추가했다.
- 브라우저에서 철회 후 포커스를 풀고 자동회전 주기보다 긴 4.5초를 기다려 재열림이 없는지 확인했다. 수정 전에는 모달이 1개 다시 나타나 실패했고 수정 후 0개로 통과했다.

GitHub 원격 CI 자체 실행은 이번 로컬 작업 범위가 아니며, 설정 추가와 로컬 동등 검증을 구분한다.

## 구현 중 결정한 범위

- 원문·제목·작가명은 등록 후 고정: 승인 재사용 위험을 줄인다. 잘못 등록하면 수정 흐름을 추가해야 하는 제약이 있다.
- 거절 상태 전이를 지원하기 위해 설계 표에서 빠진 `/reject` API를 추가했다. 관리해야 할 엔드포인트가 하나 늘어난다.
- 작가 AI 미사용 확인일을 운영자 검수일과 분리하고 허락 증빙을 필수화했다. 운영자의 입력 단계가 늘지만 서로 다른 확인을 한 필드로 대체하지 않는다.
- 에이전트 사용량 한도로 주 에이전트가 구현을 이어받았다. 독립 구현 컨텍스트가 줄어드는 대신 별도 최종 리뷰와 실제 DB/브라우저 검증을 수행했다.
