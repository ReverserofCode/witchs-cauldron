# 팬카페 허락 요청 자동화 구현·검증 기록

작성일: 2026-09-18. 작업 브랜치: `codex/fanart-outreach-20260918`.

## 결과와 범위

등록된 팬아트 후보에 대한 허락 요청 댓글, 원작자 답변 수집, 운영자의 허락·비생성형 검수, 비공개 이미지 준비, 정확한 이미지 최종 승인 후 자동 게시 흐름을 구현했다. 모든 실제 카페 조회·댓글 작성·이미지 준비·최종 게시 단계는 지정 운영 계정의 네이버 로그인 확인에 의존한다.

**로컬 구현·격리 검증 결과이며 실제 네이버 댓글 작성이나 운영 배포 결과가 아니다.** 전용 계정 로그인과 로그인 후 실제 DOM 선택자 설정은 아직 연결하지 않았다. 테스트 중 실제 카페 댓글, 작가 이미지 다운로드, 운영 DB 변경, 푸시·배포는 하지 않았다.

## 주요 작업 과정

1. 기존 배포 코드와 동일한 트리에서 별도 작업 브랜치를 사용했다. 원래 작업 폴더의 미커밋 문서는 보존했다.
2. 기존 PostgreSQL 작품 레코드·버전 검증·감사 기록을 재사용하고, 브라우저 작업은 별도 CLI로 분리했다.
3. 전송 전 영구 점유 상태를 저장하여 재시작·시간 초과가 중복 댓글로 이어지지 않게 했다. `sending`·`uncertain`은 자동 재전송하지 않는다.
4. 원작자의 직접 답변 및 이용 범위를 운영자가 검토한다. 준비 이미지의 실제 해시와 최종 승인을 묶고, 게시 전 원문·답변·파일을 다시 확인한다.
5. 댓글에 식별표를 붙이는 책임이 두 모듈에 중복된 것을 통합 점검에서 발견해 제공자 모듈 한 곳으로 통일했다. 회귀 테스트를 추가했다.
6. 독립 리뷰에서 지적된 입력 후 로그인·CAPTCHA 재검사, 모든 조회의 계정 확인, 식별 가능한 전송 불확실 오류를 수정했다.
7. 관리자 실제 화면과 테스트 DB를 연결하여 자동화 흐름 및 기존 수동 등록 흐름을 검증했다.
8. 최종 전체 리뷰에서 발견한 새 원작자 답변 누락과 입력 중 원문 이동 문제를 수정했다. 해당 요청 스레드의 원작자 답변 집합을 승인에 묶고, 제출 직전 원문 URL·실제 iframe·작성자·내용 지문을 재검증한다. 구형 승인 기록은 자동 보완하지 않고 재검토한다.

## 검증 결과

구현 검증 대상 커밋: `672b466` (최종 문서 커밋은 별도). 로컬 도구 Node 25.5.0, 배포 이미지 빌드와 웹 서버는 Node 22 Alpine을 사용했다. 전체 Vitest·실제 PostgreSQL 검증은 Node 22 builder 컨테이너에서도 같은 결과로 통과했다.

| 검증 | 결과 |
|---|---|
| 전체 Vitest + 실제 루프백 PostgreSQL | Windows 및 Node 22 컨테이너 각각 43개 파일, 301개 통과, 16개 선택적 타 기능 DB 통합 테스트 건너뜀 |
| 브라우저 제공자 격리 테스트 | 실제 Chromium, 39개 통과, 건너뜀 없음 |
| `npm run typecheck` | 통과 |
| 작업 범위 ESLint | 오류·경고 없음 |
| 전체 `npm run lint` | 오류 0개, 기존 경고 22개 |
| `docker build -t witch-fanart-outreach:20260918 ./frontend` | Node 22 프로덕션 빌드 통과 |
| `npx tsx scripts/smoke-fanart-outreach.ts` | 관리자 전체 흐름 통과 |
| `node scripts/smoke-fanart.mjs` | 기존 수동 등록·갤러리·철회·모바일 회귀 통과 |

주요 검증 사례:

- 정확한 로그인 계정, 계정 누락·불일치·중복·잘못된 회원 링크 차단.
- 댓글 입력 중 CAPTCHA 출현 또는 계정 변경 시 전송 횟수 0.
- 중복 식별표, 한 번의 제출, 결과 불명확 시 재전송 금지.
- 잘못된 게시판·원작자·AI 명시 제목·이미지 없는 원문 차단.
- 원작자의 요청 댓글에 대한 답변만 검수 대상으로 사용; 무응답은 허락이 아님.
- 게시 승인 후 로그인 만료 시 공개되지 않음.
- 비공개 미리보기 무인증 401, 준비 파일의 해시 불일치 차단.
- 답변 변경·동시 거절·취소·버전 충돌·작업자 재시작 시 안전한 상태 유지.
- 확인 후 새 원작자 답변 추가, 선택하지 않은 원작자 답변 수정·삭제도 준비·게시 전에 승인 무효화. 무관한 댓글과 표시 순서 변경은 제외.
- 입력 중 주소·iframe 자체 이동·원작자·제목·이미지·게시판 변경 시 제출 횟수 0. 새 요청 식별표가 나타나도 중복 제출하지 않음.
- 공개 응답은 `id`, `src`, `alt`, `credit`, `sourceUrl`, `publishedAt` 여섯 필드만 유지.
- 게시 철회 후 이미지 404, 갤러리 제거, 기존 수동 흐름 유지.
- HTTPS 이미지 호스트 제한, DNS 고정, 사설 IP·리디렉션·시간 초과·용량 초과 차단.

브라우저 제공자 테스트의 네트워크는 전부 가로채 테스트 HTML로 응답하거나 차단했다. 관리자 자동화 테스트는 실제 로컬 앱·DB를 사용하되 카페 제공자와 이미지는 자체 테스트 자료를 사용했다. 테스트 서버의 YouTube API 키 미설정 경고와 기존 YouTube 실패 경로 테스트의 의도적인 503 로그는 예상된 테스트 환경 출력이다. 최종 컨테이너 헬스체크는 정상이다.

## 리뷰 기록

- 핵심 워크플로/API/관리자/CLI: 요구사항 충족, 품질 승인. 필수 수정 사항 없음.
- 브라우저 제공자: 첫 리뷰 필수 수정 3건을 처리하고 재리뷰 통과. 관련 비활성 입력·영역 격리·정상 iframe 테스트도 추가했다.
- 전체 브랜치 최종 리뷰: Important 2건을 한 번의 수정 묶음으로 해결하고 범위 재리뷰 통과. 최종 미해결 Critical/Important 없음. 회귀 테스트는 실제 PostgreSQL 29개 및 브라우저 39개로 확인했고 이후 전체 검증도 통과했다.
- React 점검에서 신규 UI의 명시적 사용자 동작, 버전별 상태 초기화, 무인증 이미지 노출 방지와 기존 관리 흐름 분리를 확인했다. 기존 타 화면의 경고를 이 작업에 섞어 수정하지 않았다.

## 진행 중 적용한 판단

- 사용자 지시에 따라 플랫폼 허용 여부 확인을 **개발의 차단 조건**으로 두지 않았다. 실제 서비스·계정 제약은 별도로 남아 있으므로 이 구현을 운영 가능성 검증으로 해석하면 안 된다.
- 첫 버전은 운영자가 등록한 후보와 준비 파일의 최종 검토를 유지했다. 따라서 새 글 자동 발견·과거 글 일괄 요청·완전 무인 허락 판단은 포함하지 않는다.

## 운영 전 남은 작업

1. 비공개 경로에 전용 네이버 프로필을 만들고 의도한 계정으로 직접 로그인한다.
2. 실제 로그인 화면에서 회원 키·원작자·게시판·댓글 ID·부모 댓글 ID·작성 영역·제한 화면 선택자를 확인한다. 저장소의 예제 선택자는 테스트용이다.
3. 작업자와 웹 서버의 DB 및 비공개 이미지 저장소를 연결한다. 현재 프론트엔드 이미지가 별도 작업자를 자동 기동하지 않는다.
4. 기본 dry-run과 로그인된 원문 조회를 먼저 확인한다. 실제 댓글 쓰기·사이트 게시는 별도 운영 실행 단계로 다룬다.
5. 공개 후 허락 철회 요청은 운영자가 계속 확인해야 한다. 이 버전은 이미 게시된 글의 답변을 지속 감시하거나 자동 철회하지 않는다.

세부 환경 변수·명령·실패 대응: [운영 가이드](FANART_OUTREACH_AUTOMATION.md).

로컬 검증용 웹·DB 컨테이너는 검증 종료 후 중지한다. 재현용 이미지와 테스트 데이터는 유지하며, 운영 데이터나 개인 브라우저 프로필은 변경하지 않는다.
