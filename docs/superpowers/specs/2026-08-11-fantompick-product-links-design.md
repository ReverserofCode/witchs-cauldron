# 팬텀픽 공식 상품 이미지 링크 설계

> 상태: 사용자 승인 설계
> 작성일: 2026-08-11
> ScopeTag: `frontend`

## 배경

모잉 「여름의 공방」 프로모션 카드는 상품명·가격·특전만 표시하고 있다. 사용자는 실제 상품 이미지를 더 쉽게 확인하기를 원하지만, 팬텀픽 또는 권리자로부터 이미지 저장·재게시·핫링크 허가를 받지 않은 상태다.

공식 팬텀픽 카테고리와 상품 상세 5개를 확인한 결과 각 상세는 워터마크가 포함된 대표 이미지를 제공한다. 그러나 팬텀픽 이용약관은 사전 승낙 없는 복제·송신·출판·배포 등을 제한한다. 따라서 이 변경은 공식 이미지를 사이트에 복제하거나 원격 로딩하지 않고, 사용자가 팬텀픽의 공식 상품 상세에서 이미지를 확인하도록 연결한다.

## 목표

- 기존 5개 상품 타일에서 각 상품의 공식 팬텀픽 상세 페이지로 이동할 수 있게 한다.
- 링크가 실제 상품 이미지를 확인하는 경로임을 명확히 안내한다.
- 상품별 클릭을 기존 Analytics 계약으로 구분해 측정한다.
- 모바일·키보드·스크린리더 사용자가 안전하게 링크를 사용할 수 있게 한다.
- 이미지 저작물, 신규 의존성, 런타임 팬텀픽 요청을 프로젝트에 추가하지 않는다.
- PR CI와 기존 CD를 거쳐 운영 배포하고 비파괴 스모크 결과를 기록한다.

## 비목표

- 팬텀픽 이미지 다운로드, 변환, 저장, 캐싱 또는 핫링크
- 공식 이미지의 스크린샷·썸네일·OG 이미지 재사용
- 모잉 캐릭터나 상품 디자인을 모사한 대체 이미지 제작
- 팬텀픽 재고·가격·판매 상태의 런타임 동기화
- 기존 배너, 캠페인 기간, 종료 타이머 또는 상품 가격 변경

## 데이터 설계

`PromotionProduct`에 다음 정적 필드를 추가한다.

- `id`: DOM key와 Analytics ID에 사용하는 안정적인 영문 식별자
- `detailUrl`: 해당 상품의 추적 파라미터 없는 공식 팬텀픽 상세 URL

상품명, 가격, 선택적 특전 문구는 기존 필드를 그대로 사용한다. 이미지 URL, 이미지 대체 텍스트, 원격 호스트 설정은 추가하지 않는다.

## UI와 접근성

기존 상품 타일의 상품명·가격·특전 아래에 `공식 이미지 보기` 링크를 추가한다.

- 링크는 새 탭에서 열고 `rel="noopener noreferrer"`를 사용한다.
- 접근 가능한 이름은 상품명을 포함해 `<상품명> 공식 이미지 보기, 새 탭에서 열림`으로 제공한다.
- 링크는 최소 44px 높이의 키보드 포커스 가능한 보조 CTA로 표시한다.
- 기존 1열 모바일·2열 반응형 상품 그리드를 유지하고 가로 오버플로를 만들지 않는다.
- 상품 목록 아래 안내 문구를 `상품 이미지는 팬텀픽 공식 상세에서 확인해 주세요.`로 명확히 한다.
- 기존 카테고리 CTA와 전역 배너 UI는 변경하지 않는다.

상품 타일이나 카드 내부에 `<img>`, CSS 원격 배경, OG 미리보기 또는 팬텀픽 이미지 URL을 렌더하지 않는다.

## Analytics

각 상품 링크는 기존 메뉴 클릭 수집 규칙을 재사용한다.

| 속성 | 값 |
|---|---|
| `data-analytics-menu` | `true` |
| `data-analytics-id` | `moing-summer-atelier-2026:product:<상품 ID>` |
| `data-analytics-label` | `<상품명> 공식 이미지 보기` |
| `data-analytics-location` | `merch_promotion_product` |
| `data-analytics-type` | `promotion_product` |

Analytics API·DB 스키마는 변경하지 않는다. 브라우저 스모크에서 생성되는 합성 요청은 기존처럼 컨텍스트에서 HTTP 204로 차단한다.

## 오류 처리와 운영

팬텀픽 상세 상태를 런타임에 조회하지 않으므로 외부 사이트 장애가 마녀의 포션 공방 렌더링이나 빌드에 영향을 주지 않는다. 팬텀픽 상세가 이동·삭제되면 새 탭의 외부 페이지에서만 오류가 발생한다.

배포 전에 5개 공식 URL의 HTTP 200과 최종 도착 호스트 `fantompick.com`을 읽기 전용으로 확인한다. URL이 변경되면 정적 캠페인 데이터·단위 테스트·스모크 기대값·운영 가이드를 같은 변경에서 갱신한다.

`next.config.js`의 이미지 원격 패턴은 변경하지 않는다. 이미지 권한을 나중에 확보하더라도 별도 승인 설계와 배포로 다루며 이 변경에 자동 포함하지 않는다.

## 테스트 전략

구현은 테스트 주도로 진행한다.

1. 단위 테스트에 5개 상품 ID와 정확한 상세 URL 기대값을 먼저 추가하고, 데이터 필드가 없어 실패하는 RED를 확인한다.
2. URL이 모두 고유하고 HTTPS `fantompick.com`이며 상품 번호 375~379에 일대일 대응하는지 검증한다.
3. 브라우저 스모크에 상품 링크 5개, 접근 가능한 이름, 정확한 `href`, `_blank`, `noopener noreferrer`, Analytics 속성을 먼저 추가해 RED를 확인한다.
4. 프로모션 카드가 팬텀픽 이미지 URL·원격 이미지 요소를 포함하지 않는지 검증한다.
5. 390px에서 링크가 44px 이상이고 문구 잘림·가로 오버플로가 없는지 확인한다.
6. 전체 Vitest, TypeScript, 변경 범위 ESLint, 전체 lint 기준선, production build와 인증된 promotion smoke를 실행한다.
7. 1440px·1024px·390px와 인증된 관리자 화면을 캡처해 기존 카드·배너·관리자 제외 동작의 시각 회귀를 검토한다.

## 문서 변경

`docs/SUMMER_ATELIER_PROMOTION.md`에 다음을 기록한다.

- 이미지 재게시 권한이 없어 공식 이미지를 저장·핫링크하지 않는 정책
- 상품별 `공식 이미지 보기`가 팬텀픽 상세 페이지로 이동한다는 동작
- 상세 URL 변경 시 데이터·테스트·문서를 함께 갱신하는 절차

기존 2026-08-11 최초 배포 기록은 당시 배포 사실을 보존한다. 이번 변경이 운영 배포되면 실제 merge SHA, CD run과 운영 스모크를 별도 후속 배포 기록으로 작성한다.

## 배포와 롤백

새 기능 브랜치를 GitHub에 게시하고 PR CI가 성공한 뒤 `main`에 병합한다. 정확한 merge SHA의 CD `build-and-test`와 `deploy` job을 완료까지 감시한다.

운영 검증 항목은 다음과 같다.

- `/api/health`의 `ok=true`
- 홈과 `/broadcasts`의 HTTP 200
- 비인증 `/admin/analytics`의 HTTP 401
- 활성 홈 카드의 상품 상세 링크 5개와 정확한 공식 URL
- 새 탭 보안 속성, 상품별 Analytics 속성, 390px 오버플로·조작 영역
- 브라우저 스모크 Analytics 요청의 HTTP 204 차단

잘못된 URL이나 UI 회귀가 발견되면 force-push 또는 reset 대신 정상 `git revert` 커밋으로 롤백하고 CD를 다시 실행한다. 링크 추가는 캠페인의 `2026-09-01T00:00:00+09:00` 자동 종료 정책을 변경하지 않는다.

## 승인 기준

- 공식 이미지 파일·URL·핫링크·원격 CSS 배경이 저장소와 렌더 결과에 추가되지 않는다.
- 활성 카드에 정확히 5개의 공식 상세 링크가 표시된다.
- 모든 링크가 상품명 포함 접근성 이름, 새 탭 보안 속성, 상품별 Analytics 계약을 충족한다.
- 모바일에서 44px 조작 영역과 무오버플로가 유지된다.
- 기존 캠페인 시간·가격·배너·세션 닫기·관리자 제외 동작이 회귀하지 않는다.
- 로컬 전체 게이트, 독립 코드 리뷰, PR CI, CD와 운영 스모크가 모두 성공한다.
