## 2. 목표와 성공 조건

판매 기간 동안 사이트 어느 공개 페이지에서든 캠페인을 발견할 수 있게 하고, 홈에서는 구매 판단에 필요한 핵심 정보를 제공한다. 기간이 끝나면 운영자가 수동 배포하지 않아도 홍보 UI가 사라져야 한다.

성공 조건:

1. 공개 페이지에는 간결한 전역 띠배너가, 홈에는 상세 홍보 카드가 노출된다.
2. 시작 전과 종료 후에는 두 UI가 모두 렌더링되지 않는다.
3. 종료 경계는 홈페이지의 5분 ISR 주기와 관계없이 브라우저에서 즉시 반영된다.
4. 사용자는 띠배너를 현재 브라우저 세션 동안 닫을 수 있지만 홈 상세 카드는 계속 찾을 수 있다.
5. CTA는 추적 파라미터가 없는 팬텀픽 canonical 카테고리로 연결된다.
6. 배너·카드 클릭과 홈 카드 노출을 기존 Analytics에서 구분해 확인할 수 있다.
7. 외부 상품 이미지나 상세 HTML을 복제하지 않고도 현재 사이트와 어울리는 여름 캠페인 시각을 제공한다.

## 4. 선택한 접근과 대안

### 선택: 전역 띠배너 + 홈 상세 카드

띠배너가 `/broadcasts` 같은 공개 하위 페이지 방문자에게도 캠페인을 알리고, 홈 상세 카드가 상품·특전·마감 정보를 충분히 제공한다. 자동 팝업 없이 발견성과 사용자의 통제권을 함께 확보한다.

### 대안 1: 홈 상세 카드만

구현은 가장 단순하지만 홈을 거치지 않는 방문자가 캠페인을 발견하지 못한다. 사용자 요청의 “그 기간 동안 게시” 목적에 비해 노출 범위가 좁아 제외한다.

### 대안 2: 자동 팝업

주목도는 높지만 반복 방문 방해, 포커스 관리, 스크롤 잠금, 닫기 상태 저장 등 접근성과 상태 복잡도가 커진다. 비공식 팬 커뮤니티의 사용성을 해칠 수 있어 제외한다.

### 홈 상세 카드

- 위치: 홈 히어로 직후, 기존 생일 배너와 추천 영상 섹션 이전

- CTA: `팬텀픽에서 굿즈 보기`
- 고지: `가격·판매 상태·배송 조건은 팬텀픽에서 최종 확인해 주세요.`
- 디자인: 기존 보라색 브랜드 토큰에 여름 하늘색 그라데이션, 빛·물결·별 장식을 CSS로 조합한다. 기존 사이트 자산 이외의 외부 이미지는 사용하지 않는다.

## 6. 캠페인 데이터와 시간 모델

캠페인 정보는 외부 페이지를 런타임에 요청하지 않는 정적 TypeScript 구성으로 관리한다.

```ts
interface PromotionProduct {
  name: string;
  price: string;
  note?: string;
}

interface PromotionCampaign {
  id: string;
  title: string;
  storeUrl: string;
  startAt: string;
  endAtExclusive: string;
  shippingFrom: string;
  products: PromotionProduct[];
}
```

기준값:

```ts
startAt: "2026-08-05T19:00:00+09:00"
endAtExclusive: "2026-09-01T00:00:00+09:00"
storeUrl: "https://fantompick.com/category/%EB%AA%A8%EC%9E%89/110/"
```

종료 시각을 `2026-08-31T23:59:59`처럼 표현하지 않고 다음 날 00:00의 배타적 경계로 표현해 밀리초 오차를 없앤다.

순수 함수는 다음 상태를 반환한다.

- `upcoming`: `now < startAt`
- `active`: `startAt <= now < endAtExclusive`
- `ended`: `endAtExclusive <= now`

남은 시간은 일·시간·분으로 내림 계산하되, 1분 미만이 남았을 때는 `곧 마감`으로 표시한다. 시작·종료 경계와 잘못된 날짜 구성은 단위 테스트한다.

## 7. 렌더링과 상태 구조

홈은 5분 ISR을 사용하므로 서버 렌더링 시각만으로 캠페인을 제어하면 시작·종료가 늦어질 수 있다. 따라서 작은 클라이언트 경계 안에서 현재 시각을 확인한다.

```text
정적 캠페인 구성
  -> 캠페인 상태/남은 시간 순수 함수
  -> 공통 클라이언트 시간 훅
       -> 전역 PromotionBanner
       -> 홈 PromotionCard
```

- 서버와 첫 클라이언트 렌더는 모두 프로모션 영역을 비워 hydration 불일치를 막는다.
- 마운트 직후 브라우저 시각으로 상태를 계산해 활성 기간에만 UI를 표시한다.
- 활성 중에는 분 표시를 갱신하고, 종료 경계에는 별도 타이머를 걸어 즉시 숨긴다.
- 시작 전에도 시작 경계 타이머를 등록해 새로고침 없이 표시될 수 있게 한다.
- 타이머는 컴포넌트 해제 시 정리한다.
- 브라우저 시각이 잘못된 경우까지 교정하기 위한 서버 동기화는 이번 범위에서 제외한다.

띠배너 닫기 키:

```text
wc:promotion:moing-summer-atelier-2026:dismissed
```

저장소 접근이 차단되면 현재 페이지에서만 닫히며, 기능과 외부 링크는 계속 동작한다.

## 9. Analytics

별도 API나 스키마를 추가하지 않고 기존 이벤트 계약을 사용한다.

### CTA 클릭

기존 전역 위임 방식인 `data-analytics-menu` 속성으로 `menu_click`을 기록한다.

띠배너:

```json
{
  "type": "menu_click",
  "element": {
    "type": "promotion_cta",
    "id": "moing-summer-atelier-2026:banner",
    "label": "팬텀픽에서 보기"
  },
  "metadata": {
    "location": "merch_promotion_banner"
  }
}
```

홈 카드:

```json
{
  "type": "menu_click",
  "element": {
    "type": "promotion_cta",
    "id": "moing-summer-atelier-2026:card",
    "label": "팬텀픽에서 굿즈 보기"
  },
  "metadata": {
    "location": "merch_promotion_card"
  }
}
```

### 카드 노출

활성 상태에서만 `SectionTracker`를 렌더링하고 `promotion-summer-atelier` 섹션 ID를 사용한다. 기존 세션당 1회, 55% 가시성 정책을 그대로 따른다.

관리자 대시보드에는 다음 한글 라벨을 추가한다.

- `promotion-summer-atelier` → `여름의 공방 굿즈 홍보`
- `merch_promotion_banner` → `굿즈 전역 배너`
- `merch_promotion_card` → `굿즈 홈 카드`

분석 전송 실패는 CTA 이동이나 화면 렌더링을 막지 않는다.

## 10. 접근성·보안·표현 원칙

- CTA는 실제 `<a>`를 사용하고 새 탭 동작을 문맥상 알린다.
- 외부 링크에는 `target="_blank"`와 `rel="noopener noreferrer"`를 적용한다.
- 닫기는 실제 `<button>`과 구체적인 `aria-label`을 사용한다.
- 카운트다운은 `role="timer"`를 사용하되 분 단위 변경을 매번 스크린리더에 강제 알리지 않는다. 정확한 종료 시각을 별도 텍스트로 제공한다.
- 색상만으로 기간 한정이나 마감을 전달하지 않는다.
- 움직이는 장식은 추가하지 않으며 `prefers-reduced-motion` 사용자의 경험을 해치지 않는다.
- 외부 HTML을 주입하지 않고 정적 문자열만 렌더링한다.
- 공식 상품 이미지를 저장소에 복제하거나 외부 서버에서 핫링크하지 않는다.
- “2026-08-10 확인 기준”이라는 조사 특성을 문서에 남기고 UI에는 판매처 최종 확인 고지를 제공한다.
- 품절 여부는 언제든 바뀔 수 있으므로 `재고 있음`, `지금 구매 가능` 같은 표현은 사용하지 않는다.

## 11. 실패 처리

- 캠페인 날짜 구성이 유효하지 않으면 프로모션을 표시하지 않고 개발 환경에서 진단 가능한 값을 반환한다.
- `sessionStorage` 읽기·쓰기가 실패해도 띠배너와 CTA는 정상 동작한다.
- Analytics 요청이 실패해도 외부 링크 이동을 유지한다.
- 팬텀픽이 일시적으로 응답하지 않아도 사이트 렌더링은 영향을 받지 않는다. CTA는 공식 URL로 이동하며 외부 상태를 사이트가 대리 표시하지 않는다.
- 자바스크립트가 비활성화되면 정확한 기간 경계를 우선하기 위해 프로모션을 표시하지 않는다.

3. 일·시간·분 카운트다운과 `곧 마감` 테스트
4. 잘못된 날짜·역전된 기간 구성 테스트
5. TypeScript 타입 검사
6. ESLint 검사
7. 전체 프론트엔드 테스트

## 13. 배포와 운영

1. 구현 브랜치에서 자동 검증과 브라우저 검증을 완료한다.
2. 변경 범위와 민감정보 포함 여부를 검토한다.
3. 커밋 후 원격 브랜치에 푸시한다.
4. 기존 프로젝트 CD 절차로 운영 배포한다.
5. 배포 후 공개 홈, `/broadcasts`, `/admin/analytics`, `/api/health`를 비파괴 점검한다.
6. 운영 화면에서 배너·카드·CTA를 확인하고 프론트엔드 로그의 신규 오류를 점검한다.
7. 배포 결과와 검증 근거, 알려진 제약을 운영 문서에 남긴다.

판매 종료 후에는 UI가 자동으로 숨겨지지만, 코드는 후속 캠페인 재사용 여부를 검토한 뒤 별도 정리한다. 날짜나 가격을 수정할 때는 공식 판매처와 팬카페 공지를 다시 확인하고 테스트 기준값도 함께 갱신한다.

## 14. 알려진 제약

- 브라우저 시각이 크게 잘못되면 노출 시각도 어긋날 수 있다.
- 상품 가격·판매 상태는 실시간 동기화되지 않는다.
- 공식 이미지 재사용 권한을 확인하지 않았으므로 텍스트와 프로젝트 기존 자산만 사용한다.
- 팬텀픽의 외부 장애나 정책 변경은 사이트에서 감지하지 않는다.
- 판매 원문의 시간대 표기는 명시적 `KST`가 아니라 한국 서비스 문맥에 따른 해석이다.
